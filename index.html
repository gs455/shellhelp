examples

    what's the difference? shells vs terminals

    terminal vs shell

    The terminal is the window that shows text and takes keystrokes (Windows Terminal, macOS Terminal, iTerm2, GNOME Terminal). The shell is the program inside it that reads your command, interprets it and runs it. One terminal can host any shell.

    the shells

    • PowerShell: the modern Windows shell. Pipes pass .NET objects, not text (Get-Process | Sort-Object CPU). Windows PowerShell 5.1 ships with Windows; PowerShell 7 (pwsh) is cross-platform on Windows, macOS and Linux.
    • cmd: the legacy Windows Command Prompt, descended from MS-DOS. Text-based, uses .bat/.cmd batch scripts, limited but still everywhere.
    • bash: the default on most Linux distributions. POSIX-style, text pipelines, GNU tools (find, grep, sed).
    • zsh: the macOS default since Catalina. Mostly bash-compatible syntax, but macOS ships BSD tools whose flags differ from GNU (e.g. sed -i '', stat, date).
    • fish: friendly, with autosuggestions and highlighting out of the box. Not POSIX-compatible, so bash syntax like $(...) or VAR=x often differs.

    Note: WSL runs a real Linux distribution on Windows, so its bash behaves like Linux. Git Bash is bash ported to Windows (MSYS2) with a smaller set of Unix tools and Windows paths underneath.

    how a command runs

    • The shell parses the line into words, operators and redirections.
    • It expands variables, wildcards (*.txt), quotes and substitutions.
    • It runs a builtin (like cd) itself or launches an external program found on PATH.
    • Pipes (|) feed one command's output into the next: text in bash/zsh/fish/cmd, objects in PowerShell.

    why the same task differs

    • Different syntax for variables, quoting, loops and wildcards.
    • Different built-in tools: dir vs ls vs Get-ChildItem; GNU vs BSD flags.
    • Different paths and conventions: C:\ and \ on Windows, / on Unix.
